# 업무 기록 보관

## Decisions

- 업무 기록은 계정에 묶어 Supabase Cloud에 보관한다. 브라우저에만 두지 않는다.
- 인증은 Supabase Auth를 쓰고, 기본은 이메일과 비밀번호다.
- 권한은 본인 것만 읽고 쓰는 수준으로 잡는다. 다른 사용자의 기록은 읽을 수도 고칠 수도 없다.
- Supabase 관련 작업을 시작할 때는 모델 기억이 아니라 현행 공식 문서와 설치된 공식 스킬을 그 시점에 읽는다. 경로와 갱신 방법은 `AGENTS.md`의 `supabase-live-docs` 블록에 있다.

## Boundaries

- 이 계약은 기록을 어디에 두는지를 정한다. 테이블 구조, 마이그레이션 방식, 정책 작성 방법은 정하지 않는다. 그건 공식 Postgres 스킬과 각 작업 단위 스펙이 다룬다.
- 팀 공유나 다중 사용자 협업을 허용한다는 뜻이 아니다. 한 사람이 자기 기록을 여러 기기에서 이어 쓰기 위한 것이다.

## Why

이 도구의 약속 중 하나는 연말에 KPI를 쓰거나 업무 재분배를 협의할 때 한 일과 들인 시간을 근거로 꺼내 쓰는 것이다. 그러려면 기록이 최소 1년 이상 살아남아야 한다. 브라우저 저장은 브라우저 데이터를 지우거나 기기를 바꾸면 사라지므로 이 약속과 정면으로 충돌한다.

또한 기록은 첫 구현 시점부터 쌓이기 시작해 이후 기능(소요 시간 추정, 월별·연간 정리)의 재료가 된다. 나중에 저장 방식을 옮기면 그동안 쌓인 것을 잃을 위험이 있어, 처음부터 서버에 두는 편이 싸다.

## Reconsider when

- 사내 정책상 외부 호스팅 서비스에 업무 기록을 둘 수 없다는 제약이 확인될 때
- 한 사람이 한 기기에서만 쓴다는 것이 확정되고, 별도의 백업 경로가 생겼을 때

## Still-rejected alternatives

- 브라우저 저장만 사용 — 가장 단순하지만 브라우저 데이터를 지우거나 기기를 바꾸면 기록이 사라진다. 연말에 근거로 꺼내 쓴다는 약속을 지킬 수 없다.
- 브라우저 저장에 파일 내보내기·가져오기를 더하기 — 서버 없이 돌면서 기록을 옮길 수는 있으나, 백업을 사용자가 직접 챙겨야 해서 챙기지 않은 시점에 유실된다.
